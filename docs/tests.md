# Тест-план и матрица тест-кейсов

Задача #15. Аналитик: kahmarr. Версия 26.10.2026.

Цель: проверить ввод ключа, движение по матрице, ошибки, блокировку и работу серво по блок-схеме и задачам #8–#16. Для приёмки необходимы исполнение всех применимых сценариев и повторная проверка исправленных дефектов.

## Два варианта проекта

Физический стенд: Uno/Nano + WS2812B 4×4. Проверенный вариант симулятора: Mega + MAX7219 8×8 + LCD I2C. Команда подтвердила, что Mega/8×8 используется только для симуляции. Результаты этого прогона не подтверждают работоспособность физического стенда или драйвера WS2812B.

Основа: [блок-схема #5](https://github.com/Mys2018/Arduino-based-pattern-lock/issues/5), [требования #15](https://github.com/Mys2018/Arduino-based-pattern-lock/issues/15), исходник [из #9](https://github.com/Mys2018/Arduino-based-pattern-lock/issues/9#issuecomment-6399289981). Полная версия и ограничения — [test-report.md](test-report.md).

## Подготовка

1. Открыть Wokwi Mega, загрузить исходный graphic_lock_wokwi.txt как sketch.ino, qa-diagram.json как diagram.json и библиотеки из qa-libraries.txt.
2. Для первой записи использовать пустую EEPROM. Сохранить тестовый ключ P.
3. Координаты симулятора: строки/столбцы 0–7. Длина ключа 4 точки. P=(0,0)→(0,1)→(1,1)→(1,2); Q=(0,0)→(1,0)→(1,1)→(2,1). Номера P=0,1,9,10; Q=0,8,9,17.
4. В Serial: w/a/s/d — перемещения, e — подтверждение. Из (0,0) P вводится `edsde`, Q — `esdse`. После ошибки первая точка остаётся, поэтому следующая Q — `sdse`. Не отправлять несколько попыток одной длинной строкой: дождаться состояния INPUT_PATH.
5. Джойстик в коде обрабатывается в INPUT_PATH. Выбор первой точки выполнялся через Serial; не выдавать это за подтверждённый автономный ввод только стиком.
6. Каждый независимый случай начинать с известного состояния. TC-09–14 выполнять последовательно. В физической версии для нижней/правой границы заменить 7 на 3 и повторить проверки.

## Матрица

«ПК» означает модель логики со стандартными заглушками периферии, а не Wokwi/Arduino. Частичный результат не равен полному прохождению.

| ID | Проверка | Шаги | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|---|---|
| TC-01 | Запуск | Запустить с сохранённым P. | Замок закрыт, серво 0°, доступен выбор старта. | Wokwi: запуск и приглашение ввода; ПК: CHOOSE_START, 0°. | Пройдено |
| TC-02 | Выбор старта | В CHOOSE_START нажать d, затем a. | Выбор перемещается, ввод пути ещё не начат. | Через Serial выбран старт; точное перемещение по всем клеткам отдельно не проверено. | Частично |
| TC-03 | Подтверждение старта | Выбрать (0,0), нажать e. | Первая точка записана один раз, INPUT_PATH. | Wokwi: начинается запись пути. | Пройдено |
| TC-04 | Четыре направления стика | Из внутренней точки выполнить вверх/вниз/влево/вправо с возвратом в центр. | Четыре верных соседних шага. | Полный прогон физическим управлением Wokwi не выполнен. | Не проверено |

| TC-11 | Третья ошибка | Без перезапуска снова ввести Q. | BLOCKED, серво закрыто. | Wokwi: Wrong attempt 3, BLOCKED. Длительность отдельно в TC-13. | Пройдено |
| TC-12 | Ввод во время BLOCKED | Во время блокировки отправить P и r. | Нет открытия и стирания пароля. | ПК-модель: state=BLOCKED, stored=1. | Пройдено только на ПК |

| TC-14 | Попытка после блокировки | После тайм-аута ввести Q. | Новая ошибка считается первой. | ПК-модель: attempts=1. | Пройдено только на ПК |

## Доказательства и завершение

Журнал: [wokwi_serial.txt](wokwi_serial.txt). Снимки: [успех](wokwi_success.jpg), [блокировка](wokwi_blocked.jpg). Машинные результаты ПК: [host_results.json](host_results.json), [servo_host_results.json](servo_host_results.json).

Таймер измерять по времени симуляции/millis(), а не по скорости реальных часов. Для каждого повторного прогона записать версию, шаги, наблюдение и статус. Пока остаются непроверенные сценарии и два дефекта, весь прототип не принят. Обрыв питания во время записи EEPROM, реальное питание, усилие замка и физический дребезг пока не проверялись.
